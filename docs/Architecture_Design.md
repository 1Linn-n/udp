# Архитектурный дизайн

## 1. Выбор жанра и топологии

* **Жанр (пример для сквозного проекта):** FPS-арена до 8–16 игроков.
  Частые мелкие команды (движение 10–20 Гц, выстрелы), допустимая задержка
  < 100 мс, состояние — позиции игроков.
* **Топология: Dedicated Server (авторитетный выделенный сервер).**

| Критерий | Dedicated | Listen | P2P | Relay | Вывод |
|---|---|---|---|---|---|
| Число игроков | высокое | низкое | среднее | среднее | Dedicated масштабируется |
| Чит-защита | сервер — авторитет | слабая (хост-игрок) | слабая | средняя | нужен авторитет |
| Задержка | низкая (прямой UDP) | низкая | низкая, но O(n²) трафик | +хоп ретрансляции | прямой UDP лучше |
| Бюджет/сложность | средняя | низкая | высокая (NAT, консенсус) | цена ретрансляции | приемлемо для учёбы |

Решение: **Dedicated** — сервер владеет истиной (позиции, попадания),
клиент только отображает и отправляет ввод. Это прямо требует задание
(«сервер обрабатывает и возвращает обновлённое состояние»).

## 2. Распределение обязанностей

| Компонент | Обязанности | Не делает |
|---|---|---|
| UDP-сервер (авторитет) | `socket/bind/recvfrom/sendto`; проверка CRC32; авторизация; лог; хранение `PlayerState`; валидация; формирование `STATE_UPDATE`/`SHOT_RESULT` | Рендер, ввод, предсказание |
| UDP-клиент | Ввод/генерация команд; сериализация; `sendto`; ожидание ответа `select()`; печать; периодичность (таймер) | Хранение чужого состояния, решение о попаданиях |
| Common-протокол | `encode/decode`, BE-примитивы, CRC32, билдеры/парсеры payload | Сетевой ввод-вывод |

## 3. Схема классов/модулей

```text
            +------------------ Common (proto) ------------------+
            | PacketType | Header | Packet                        |
            | crc32() | put/get U16/U32/Float BE                  |
            | encodePacket() | decodePacket() -> badCrc           |
            | make*/parse* Movement/Shoot/Login/State/Shot/Text   |
            +------------------+------------------+----------------+
                               |                  |
              +----------------+                  +----------------+
              | UDP-сервер                          | UDP-клиент    |
              |----------------                     |-------------- |
              | main(): bind loop                   | main(): LOGIN |
              | users map, authed set               | loop: MOVE/   |
              | players: endpoint->PlayerState      |  SHOOT, timer |
              | logLine() -> stdout+server.log      | roundTrip()   |
              | sendto() ответ                      | printAnswer() |
              +-------------------------------------+---------------+
```

`PlayerState { x,y,z, moves, shots }` — минимальное «мир-состояние» на игрока.
Ключ — строка `ip:port` (для учебного проекта; в проде — session id/токен).

## 4. Сетевой цикл

```text
Клиент                          Сервер (авторитет)
  | LOGIN(seq=0)  --------------> | проверка users -> AUTH_OK, authed+=ep
  |<------------- AUTH_OK --------|
  |                               |
  | MOVEMENT(seq=1, x,y,z) ------> | CRC? auth? -> players[ep]={x,y,z}
  |<-------- STATE_UPDATE(ack=1) --|
  | SHOOT(seq=2, weapon) --------> | -> SHOT_RESULT(ack=2, hit)
  |<-------- SHOT_RESULT ---------|
  ... каждые interval_ms, select timeout 2000 мс ...
```

## 5. Ключевые решения

* **Порядок байт:** всё многобайтовое — big-endian вручную (`putU16BE` и т.д.),
  float — биты IEEE754 через `memcpy`. Нет зависимости от `#pragma pack` /
  выравнивания — соответствует критерию «правильность сериализации».
* **Целостность:** CRC32 IEEE в каждом заголовке (доп. задание). Несовпадение —
  дроп + `PACKET_ERROR`, лог `crc=FAIL`.
* **Авторизация:** `LOGIN` с `ulen/login/plen/password`; сервер хранит allow-list
  и множество авторизованных эндпоинтов (доп. задание).
* **Логирование:** сервер пишет каждую команду: время, эндпоинт, тип, seq, size,
  CRC-статус, декодированный payload и отправленный ответ.
* **Кроссплатформа:** `#ifdef _WIN32` — Winsock2 (`WSAStartup`, `closesocket`),
  иначе — Berkeley sockets. Сборка — CMake + MinGW (Windows) / GCC (Linux).
* **Масштабирование (задел):** цикл single-threaded достаточен для семинара;
  дальше — `select()`/потоки, тикрейт, интерполяция и клиентское предсказание.
